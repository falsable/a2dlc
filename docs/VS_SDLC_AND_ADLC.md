# A2-DLC against SDLC and the "ADLC" lifecycle

This page compares `a2dlc` (protocol v3.4, binary v0.4.0) with the two lifecycles that circulate most in 2026 talks about agent-written code:

- **SDLC**, the classic six-stage cycle: requirements and planning, architecture and design, implementation, QA and testing, release and rollout, monitor and fix.
- **ADLC** ("Agentic Development Lifecycle"), as drawn in the widely shared "From SDLC to ADLC" infographic (Rakesh Gohel, 2026): capture intent, requirements and design with the agent, agent builds with context and skills, continuous evals, agentic review with executable gates, production signals create new intent. Its artifact chain is `intent.md → spec.md → plan.md → code + tests → review record → production signal`, and "the chain of commits becomes the audit trail".

The claim this page supports is narrow: **for code whose behaviour can be executed, a2dlc decides more by execution and resists bypass better than either lifecycle.** Where that claim does not hold is listed at the end. Every row names the file, test or measurement that backs it; the test run that checked them is at the bottom.

## Stage by stage

| Stage | SDLC | ADLC (infographic) | a2dlc | Evidence |

The MCP tools always set a cost cap (2.0 USD unless given); a hand-written intent may declare `max_cost_usd: null`, and then CB-03 has nothing to enforce. A malformed intent never starts a run. | `contracts/intent.schema.json`; `toolIntentFromTicket` in `internal/mcp/server.go`, covered by `TestMCPServeProtocolAndTools` (`internal/mcp/server_test.go`); `TestBudgetFromIntent` (`internal/run/intent_test.go:469`). |
| Design | Architecture reviewed by humans in handoffs. | "Requirements and design collapse into one session, guided by policy encoded as skills." One agent, one session, no second opinion. | Stage 1 asks two model families for the contract (`S_α`, `S_β`); an Inquisitor turns their disagreement into concrete input/output probes a person answers. Stage 1.5 lints the contract, runs Z3 over the fragment of its invariant DSL that is decidable (the rest is marked `runtime_and_pbt`) and back-translates it blind to catch a spec that says something the intent did not. Two families that agree can still both be wrong (§10.1), and the back-translator can share their bias (§10.11); the design has a second opinion and a human probe, not a proof. | Protocol §5 Stages 1 and 1.5; `internal/run/machine.go:257` (family rule); `internal/dsl` (DSL to SMT-LIB); coverage row "1.5 Static contract validation" in `COVERAGE_AND_BENCHMARKS.md`. |
| Build | Developers with code review later. | "Institutional knowledge becomes CLAUDE.md. Guardrails run as hooks, not habits." | Builders run in `--network none` containers; what each role may see is code in `internal/run/policy.go`, and `roles.json` cannot widen mounts. The hooks are the harness's, not the agent's: `PreToolUse` blocks edits to protected paths and `git push --no-verify` before they run; the Stop hook exits 2, which Claude Code treats as a block. That arm (A2) uses the gold patch as the peer, so it is an upper bound; A3, the figure reachable without gold, was not measured. Repo tests with the coverage precondition alone (A1) gave 0/38 empty passes, no FAIL, and 61 % INCONCLUSIVE. |
| Release | Human approval, then rollout. | "Agentic review with executable governance. Human judgment reserved for critical code." The graphic does not say what makes code critical or who decides. | "Critical" is defined by evidence, not by opinion: a counterexample from an engine, a test that fails on another builder's tree, or a protected path. Only then does a person decide, and the decision is an SSH signature bound to the file's git blob; a later edit to the same file invalidates it. Allowed signers live outside the repository, so the agent cannot add its own key in the diff. Stage 7 writes `delivery.json` with canary rings, a Rollback Sentinel and a compensation requirement (CB-06) for writing slices. | `TestSignatureBoundToFile` (`internal/app/app_test.go:166`); `TestWaiverWithoutSignaturePassesCheckAndStopsVerify` (`:149`); `TestProtectedPathWithoutApprovalIsInconclusive` (`:561`); `internal/run/stage7.go:14`. |
| Monitor | Humans watch dashboards and open tickets. | "A production alert writes a new intent.md and flows back through the pipeline. No human starts it." The alert decides everything about the next run. | The sentinel thresholds (error-rate delta, p99 latency, runtime invariants) come from the intent's SLAs and ship in `delivery.json`; the platform executes them. The payload cannot raise the inherited cap (only lower it), cannot loosen a threshold the intent's sentinel declares (the declared value wins and the response says the payload's was ignored), and cannot overwrite an existing intent. An alert with no threshold and no sentinel to read it from is refused. An alert on a slice with no intent is accepted with the given threshold, the 2.0 USD cap and no boundary: there is nothing to inherit, and the page claims no more than that. The run it starts still stops at probes, circuit breakers and signed waivers. | `internal/run/stage7.go:24`; `toolIntentFromSignal` in `internal/mcp/server.go`; `TestIntentFromSignalInheritsBudgetInvariantsAndThreshold` (`internal/mcp/server_test.go`). |

## The artifact chain

ADLC's chain is six Markdown files and "the chain of commits becomes the audit trail". A commit records that someone wrote something. It does not record whether anyone executed the code, whether the test had teeth, or whether the tree reviewed is the tree pushed; and an agent can commit, amend and rewrite history.

a2dlc's chain is made of artifacts a machine validates and a person signs:

| ADLC artifact | a2dlc artifact | What makes it more than a file |
|---|---|---|
| `intent.md` | `.a2dlc/intents/<slice>.intent.json` | Schema-validated; carries the budget cap and the boundary. |
| `spec.md` | `.a2dlc/run/<slice>/contract.json` (`S*`) plus `lint.json` | Two families wrote it; Z3 checked the invariants; a blind back-translation audited it. |
| `plan.md` | Stage 2 route (`N=1` or `N=2`) | There is no plan to review: the route is decided from the contract's complexity and criticality, and the human sees counterexamples, not plans (§1). |
| `code + tests` | The candidate tree plus the Saboteur's suite | Tests written by a role that never saw the implementation. |
| `review record` | `.a2dlc/verdict.json` bound to the git `tree_hash`, `.a2dlc/waivers.json` and `.a2dlc/approvals.json` with SSH signatures, `ledger.json` with a SHA-256 hash chain of every container launch | The verdict is stale the moment the tree changes and names the files (`TestVerifyStaleNamesFile`, `internal/app/app_test.go:268`). `verify-run` detects a tampered or truncated ledger (`TestVerifyRunDetectsTamperedLedgerAndArtifacts`, `internal/run/resume_test.go:148`; `TestResumeWithTruncatedLedgerIsRejected`, `:101`). Gate outputs stay out of the `tree_hash` (`internal/gitx/gitx.go:20`), otherwise signing would make the verdict stale. Signed approvals are committed; CI recomputes the verdict with `check --base <before> --require-signatures` (`templates/ci/a2dlc.yml`) instead of trusting a committed one. |
| `production signal` | `delivery.json` rings, sentinel and compensation; `a2dlc_intent_from_signal` back to an intent | The rollout itself is platform-side by design (ADR 0004). The loop back inherits the alerted slice's invariants, boundary and budget cap instead of letting the alert write them. |

The pre-push hook runs `a2dlc verify` with the absolute path of the binary and fails if it cannot find it, so a missing binary never means an open gate. `check` without `--base` compares against the upstream, not `HEAD`, so a committed change cannot wash itself (`TestCheckAgainstHEADDoesNotWashCommittedChanges`, `internal/app/app_test.go:209`).

## Measured head to head: self-verification against the a2dlc gate

ADLC's Test phase is a rule: "every session verifies its own work first". Made executable it has two readings, and both were run: **changed**, the session runs the test files it changed and green (or nothing to run) means done; **suite**, the session runs the whole suite and green means done. Both readings and `a2dlc check` ran on 2026-10-22 over the nine frozen cases of `e2e/testdata/gates-py` (sha256-pinned, expected verdicts written before the gates), with real pytest in `a2dlc-tests-pytest:0.2`, `--network none`: `bash e2e/measure_gates.sh <tmp>` for a2dlc, then `bash e2e/measure_self_verification.sh <tmp>` for the two readings over the same working trees. The base ships one test that is red before any change (`tests/test_roto.py`), as real repositories do, so the suite reading is reported as what it prints and as what a session gets if it discounts the reds that were already there.

"Must block" means an expected `FAIL` or `INCONCLUSIVE`: both block the push (§6.4); `INCONCLUSIVE` escalates as a tool problem instead of a divergence.

| Case | What the candidate does | Changed files | Whole suite | Suite, base reds discounted | a2dlc check | Expected |
|---|---|---|---|---|---|---|
| C1 feature with test | New function, test fails on the base stub | GREEN | RED | GREEN | PASS | PASS |
| C2 toothless test | `pytest.raises(Exception)` also swallows the stub's `NotImplementedError` | GREEN | RED | GREEN | FAIL (`nop_oracle`) | FAIL |
| C3 bugfix with waiver | New test crashes on the base, declared waiver | GREEN | RED | GREEN | PASS | PASS |
| C4 characterization refactor | Equivalent refactor, test passes on both trees | GREEN | RED | GREEN | PASS | PASS |
| C5 red new test | New test fails on the candidate too | RED | RED | RED | FAIL | FAIL |
| C6 regression | Existing test goes green to red; no test file changed | GREEN (nothing to run) | RED | RED | FAIL (`baseline`) | FAIL |
| C7 nested method without stub | New method the engine cannot stub | GREEN | RED | GREEN | INCONCLUSIVE | INCONCLUSIVE |
| C8 run without tests | A `conftest.py` kills the process | RED | RED | RED | INCONCLUSIVE (`tooling`) | INCONCLUSIVE |
| C9 modified test file | Old tests do not count as new; the new one is characterization | GREEN | RED | GREEN | PASS | PASS |

Of the five cases that must block: the changed-files reading blocks 2 and lets 3 through (the toothless test, the regression in a file the session did not touch, the method no oracle examined); the whole-suite reading blocks all 9 cases, the 4 good ones included, because of the pre-existing red; the suite reading with the base's reds discounted blocks 3 and lets 2 through (the toothless test and the unexamined method), and the discounting is the bookkeeping a2dlc's baseline gate automates. a2dlc blocks 5 of 5 and passes the 4 that must pass, with no false block. Under the most generous reading, self-verification still passes a test that proves nothing and code that nothing examined, which is the Circular Trap stated in one table. The frozen cases are not edited.

## Where the claim does not hold

- **Work that is not executable code.** UI judgement, prose, product and architecture decisions that no test expresses. SDLC's human design review covers those; a2dlc narrows review only where an engine, a test or a signature can decide.
- **Lite mode has no Saboteur.** `a2dlc check` catches refactor divergences and toothless tests, but a misunderstanding of the spec that the same agent codifies in the code and the test at once needs the full flow (protocol §10.7). In that mode a2dlc shares part of ADLC's weakness.
- **A `PASS` is a bounded search**, recorded with its engine and budget, not a proof of equivalence (§10.8).
- **Untyped Python functions, methods and async functions** are `INCONCLUSIVE` or out of the differential's scope; their lines then need a test to pass the coverage precondition (engine table in `COVERAGE_AND_BENCHMARKS.md`).
- **Stage 7 is a plan, not an executed rollout.** The binary runs in a repository, not in production.
- **Cost and ceremony.** SDLC and ADLC cost nothing to adopt beyond a template. a2dlc needs Git, Docker and the engine images; the full flow costs real model calls. Two single runs cost 0.025 and 0.069 USD (`COVERAGE_AND_BENCHMARKS.md`, coverage rows for Stages 2 and CB-02b); cost per slice at scale is unmeasured (§10.6).
- **Only Phase 0 figures are measured** (§10.9): the thresholds, times per tier and budgets in the protocol are unvalidated, and v2 to v3.4 were refined by LLM critiques, which optimizes for passing reviews, not for production.
- **A domain guard that excludes an input where the versions differ turns a `FAIL` into a false `PASS`** (§10.10); only contract guards or mechanical over-approximations are admitted and the verdict records them.
- **Changes inside legacy code** without explicit scoping are outside the autonomous flow (§10.5); SDLC covers them with ordinary review.
- **Where a2dlc deviates from its own specification** (naming, when Occam selection runs, the Saboteur after the Builder instead of in parallel, dual-spec only from criticality `medium`, Stage 7 as a plan), the deviations table in `COVERAGE_AND_BENCHMARKS.md` says so, with the reason for each.

## How this page was checked

On 2026-10-22, `gofmt -l .`, `go vet ./...` and `go test -count=1 ./...` ran in `golang:1.23-bookworm` with `--network none` on the tree this page was written against. Every test named above passed. Two tests failed, both because that image ships `python3` and no `python`, and both are tracked in bead `a2dlc-96s`: `TestStage6AutoConsumerRunsWhenCodeGraphReachesAChange` and `TestDiscoverRunsIndexerAndReportsBlastRadius`. Neither backs a row of this page. The SWE-ABS and mutation figures are the ones already recorded in `COVERAGE_AND_BENCHMARKS.md` and `e2e/bench-swe-abs/RESULTS.md`, each with its script and frozen fixtures; they were not re-run for this page. The gates-py figures were re-run for it, with the two scripts named above.

A separate read-only review of a first draft of this page, run the same day by an agent that had not written it, re-ran every named test by name (all passed), found two citations that pointed at the wrong line, and found three ways the alert payload of `a2dlc_intent_from_signal` could decide more than the draft claimed: raise the inherited cap, loosen a declared sentinel threshold, and overwrite another slice's intent. The tool now refuses the three and `TestIntentFromSignalInheritsBudgetInvariantsAndThreshold` covers them; the review's other findings (the budget cap is not mandatory at the schema, the SWE-ABS arm is an upper bound, the costs are two single runs, the §10 limits listed above) are in the rows they concern.
