# a2dlc

A2-DLC Lite differential gate, built to serve any language and any agent: a Go core and one engine per language in Docker. Measurements in §12 of protocol v3.5 (`docs/A2-DLC_v3.5_protocol.md`).

Task tracking: beads. Run `bd prime` to see the workflow.

## Commands
Go is not installed on the host, and it will not be installed. Everything runs in `golang:1.23-bookworm`:

    MSYS_NO_PATHCONV=1 docker run --rm --network none -v "$(cygpath -w "$PWD"):/src" -w /src -v a2dlc-gocache:/root/.cache \
      -e GOFLAGS=-buildvcs=false golang:1.23-bookworm sh -c 'git config --global --add safe.directory "*"; \
      gofmt -l .; go vet ./... && go test -count=1 ./... && GOOS=windows GOARCH=amd64 go build -o dist/a2dlc.exe ./cmd/a2dlc'

- E2E of the `.exe` on Windows: `bash e2e/windows.sh <empty temporary folder>`. It uses the fake engine (`engines/fake`) and a bare remote, so the pre-push runs a real `git push`. At the end it validates every verdict the binary writes against the schema.
- The repo gates itself (`.a2dlc/config.json`): `a2dlc check` needs the image `a2dlc-engine-bb-go:0.1` built locally (commands in `engines/blackbox/*Dockerfile`). The mutants in `e2e/testdata/mutantes-bb/` are frozen by sha256: they are not edited or regenerated.
- Test gates (NOP/Oracle, baseline, flakies): `bash e2e/measure_gates.sh <empty temporary folder>` with real pytest over the frozen cases in `e2e/testdata/gates-py/` (not edited or regenerated; Spanish keys, normalized by `e2e/normalize_manifest.py`). Needs `a2dlc-engine-py:0.2` (`engines/py`) and `a2dlc-tests-pytest:0.2` (`e2e/gates/pytest.Dockerfile`, with coverage); `FIXTURE=gates-prop` needs `a2dlc-tests-hypothesis:0.1`. The judge's own tests: `python -m unittest discover -s e2e -p "test_*.py"`. What pytest cannot make deterministic (flaky) is in `internal/app/gates_test.go` with a fake runner. `bash e2e/measure_self_verification.sh <that same folder>` afterwards runs the ADLC "session verifies its own work" rule over the trees measure_gates built (docs/VS_SDLC_AND_ADLC.md).
- Current images built from this tree: `a2dlc-engine-py:0.7` (`engines/py`, 219 unit tests: `docker run --rm --network none -v "<repo>/engines/py:/engine:ro" --entrypoint python a2dlc-engine-py:0.7 -m unittest discover -s /engine -p "test_*.py"`), `a2dlc-roles:0.11` (`roles/`), `a2dlc-egress-proxy:0.1` (`roles/egress-proxy`, needed by any role with `"network": "provider"`; the ledger records its digest). Older tags (`engine-py` 0.2–0.6, `roles` 0.1–0.10) are kept for the measurements that cite them.
- Tier 0 of the declared tests (RFC-0002, bead a2dlc-eve), zero-cost in real Docker: `bash e2e/stage3_tests_tier0.sh <empty temporary folder>` after building `dist/factory.exe`; a scripted builder applies the reference fix for tinylinks #3 on a copy of the frozen target (tests-only config, no engine) and the lane must end `accepted`/PASS, while the same candidate without the fix must not. Needs `a2dlc-factory-roles-node:0.1` and `a2dlc-factory-node-cov:0.1`.
- Any-language proof of the factory (toy Python repo, fake claude, real engine and test images): `bash e2e/factory-anylang/run.sh <empty temporary folder>` after building `dist/factory.exe`; results in `e2e/factory-anylang/README.md`.
- Factory merge queue and holdout (`factory integrate`): the sealed holdout is `e2e/testdata/factory-holdout/`; run `bash e2e/factory/check_holdout.sh` before any mount (the Go verifier `factory.VerifySeal` repeats it before every mount). It is mounted read-only, network none, only on the integration branch at validation time; never open its test files or `mutants.json` to write a lane or a test, and never scan a holdout run's output for leaks (it carries the canary by design).
- The factory fixtures are frozen by sha256: `e2e/testdata/factory-holdout/` by its `SEAL` (the sha256 of its `MANIFEST.sha256`, checked by `e2e/factory/check_holdout.sh`) and `e2e/testdata/factory-ref/` by its `MANIFEST.sha256` (checked by `e2e/factory/check_fixtures.sh`). They are not edited or regenerated; a change to the holdout is a new holdout with a new seal (`e2e/factory/README.md`). The click benchmark's fixtures (bead a2dlc-3fu.21, `e2e/factory/click/README.md`) are frozen the same way and fall under the same holdout rules: `e2e/testdata/factory-holdout-click/` by its `SEAL` (`bash e2e/factory/check_holdout.sh e2e/testdata/factory-holdout-click`) and `e2e/testdata/factory-ref-click/` by its `MANIFEST.sha256` (`bash e2e/factory/click/check_fixtures.sh`).
- Contract test: it is in the README. If you change a schema, run `python contracts/tests/generate_invalid.py` and then `validate.py`.
- RFC §6.4 (the receipt) is normative and must not contradict the schemas or `gitx.Excluded`: `docker run --rm --network none -v "<repo>:/r:ro" a2dlc-contract-test python /r/contracts/tests/check_rfc.py /r` (tests: `python -m unittest discover -s /r/contracts/tests -p test_check_rfc.py`). Change a schema, the excluded paths or `WaiverSHA`/`Payload` and the RFC changes with it. `e2e/test_rfc_reference.py` (host, stdlib) checks the RFC's tree and waiver-hash rules against git and the frozen Go output in `e2e/testdata/rfc/`.
- Conformance kit (`conformance/`, README inside): `python conformance/run.py --binary dist/a2dlc.exe --engine-image a2dlc-engine-fake:0.1` (fake engine: `docker build -t a2dlc-engine-fake:0.1 engines/fake`). The vectors under `conformance/vectors/` are generated: edit `e2e/make_conformance_vectors.py`, run it, and `--check` must pass. They derive from the frozen fixtures and never edit them. Change `gitx.Excluded`, the receipt or a schema and the vectors change with it; a vector marked `known_failure` must fail, and the runner flags it when it stops failing.
- Clean-room verifier (`verifiers/python/`, README inside): Python stdlib only, written from the RFC, `contracts/` and `conformance/` without reading `internal/` or `cmd/`; do not read the Go code to "fix" it, record an RFC amendment in `verifiers/python/AMENDMENTS.md`. Tests and the conformance run are in its README (image `a2dlc-verifier-test:0.1`, built from `verifiers/python/Dockerfile`).

## Rules
- **The contract governs.** A change of shape goes first in `contracts/*.schema.json`, with valid and invalid examples; then in `internal/contract`. `TestExamplesOfContractDecode` fails if the struct and the schema drift apart.
- **`internal/run` imports `app`, never the reverse.** The state machine calls the oracle; the gates do not know it exists. The policy of what each role sees (`run/policy.go`) is code, not config: `roles.json` chooses the command and cannot widen mounts.
- **The core knows no languages.** The engine is the one that discovers the targets inside the changed files; no TS or Python logic in `internal/`.
- **Gate outputs and signatures stay out of the `tree_hash`** (`gitx.Excluded`). If they went in, approving would make the verdict stale.
- **`check` without `--base` compares against the upstream.** Against HEAD, after committing, it would not see what was committed, and an unsigned waiver would pass the push (covered by `TestCheckAgainstHEADDoesNotWashCommittedChanges`).
- **The gate is the push, never the commit.** `install` writes no pre-commit: agents commit and merge their worktrees with no human in the loop; `pre-push` (`verify`) is where a behavior change needs a signed waiver.
- **A check lowers the verdict, never raises it.** `config.checks` (protocol §5 Checks, `internal/app/checks.go`): blocking finding without a signed `accept_finding` is FAIL, blocking error or timeout is INCONCLUSIVE, advisory is recorded only; a check that cannot run is never a pass, and `severity` has no default. No host command: what runs is the image, with `--network none`.
- **Agent hooks go through `a2dlc hook <agent>`.** In Claude, the Stop hook treats exit 1 as "does not block": wiring `check` directly would let FAILs through.

## Never
- An approval signature that does not bind the file's blob: it would be valid for future changes to the same function.
- Read `allowed_signers` from the repo: the agent would add its own key in the same diff.
- Ask for, store or pass the passphrase of the signing key. ssh-keygen accepts it via stdin; the only thing that protects the signature is that the agent does not know it.
- Skip the gate when the binary is missing: the pre-push uses the absolute path and, if it cannot find it, fails.
- Put host paths (`C:/Users/...`), owner quotes or AO worker and session ids (`a2dlc-N`) in a tracked file or a commit message: the repo is public and a push publishes the whole history. Use a variable or a path relative to the repo, say "the owner approved" and not the quote, and say "a worker session" and not its id.
